# Securo native Omarchy webapp conversion — evidence

Host-config task (no product code change): the Securo launcher is now a proper
Omarchy webapp entry (browser `--app` mode window) that still starts the local
Docker stack when it is down. All changes are host files authorized by the brief;
this file records the exact commands and results.

## What changed on the host

1. `~/.local/bin/securo-launch` — replaced both `xdg-open "$FRONTEND_URL"` calls
   (fast path and post-health path) with `omarchy-launch-webapp "$FRONTEND_URL"`.
   Container-start logic, 60s bounded health wait, and critical `notify-send`
   failure path unchanged.
2. `~/.local/share/applications/Securo.desktop` — generated by
   `omarchy webapp install` with a custom exec; Comment adjusted so
   `desktop-file-validate` is fully clean.
3. `~/.local/share/applications/securo.desktop` — old plain launcher removed.
4. `~/.local/share/icons/securo-apple-touch-icon.png` — source icon kept;
   installed copy at `~/.local/share/icons/hicolor/256x256/apps/securo.png`.

Icon: local 256×256 PNG served by the app itself
(`http://localhost:8300/apple-touch-icon.png`, downloaded to the icons dir).
No remote icon fetch needed.

## Exact commands

```sh
# Read the contract first (required)
cat $(which omarchy-webapp-install)

# Icon: copy app-served local PNG into ~/.local/share/icons/
curl -sf http://localhost:8300/apple-touch-icon.png -o /tmp/securo-icon-src.png
cp /tmp/securo-icon-src.png ~/.local/share/icons/securo-apple-touch-icon.png

# Install webapp with custom exec (Exec= becomes securo-launch)
omarchy webapp install Securo http://localhost:8300 \
  "$HOME/.local/share/icons/securo-apple-touch-icon.png" \
  "$HOME/.local/bin/securo-launch"

# Exactly one Securo launcher entry + desktop database refresh
rm ~/.local/share/applications/securo.desktop
update-desktop-database ~/.local/share/applications/

# Make validation fully clean (generator sets Comment == Name)
sed -i 's/^Comment=Securo$/Comment=Personal finance manager (local Docker stack)/' \
  ~/.local/share/applications/Securo.desktop

# Validation
desktop-file-validate ~/.local/share/applications/Securo.desktop
```

## Generated entry (`~/.local/share/applications/Securo.desktop`)

```ini
[Desktop Entry]
Version=1.0
Name=Securo
Comment=Personal finance manager (local Docker stack)
Exec=/home/rehem/.local/bin/securo-launch
Terminal=false
Type=Application
Icon=securo
StartupNotify=true
```

## Verification results

- **(c) `desktop-file-validate`**: clean (exit 0, no warnings).
- **(a) Stack already up**: `gtk-launch Securo` returned in 0.04s; Chromium
  `--app` window appeared immediately (Hyprland client class
  `chrome-localhost__-Profile_1`, title "Securo"). Note:
  `omarchy-launch-webapp` falls back to chromium because the default browser
  (zen) is not in its supported list — this is the tool's own documented
  behavior and still yields a real app-mode window.
- **(b) Cold start**: after `docker compose -f ~/securo/docker-compose.prod.yml stop`
  (all 6 containers down), launching brought all 6 containers up; backend health
  OK 9s after launch; app window open ~15s after launch.
- Screenshot of the resulting app-mode window: `securo-webapp-window.png`
  (alongside this file) — standalone window rendering the Securo UI with no
  browser tabs/chrome.

Stack left running (shared local service, was up before the test).
