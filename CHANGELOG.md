# Squad distro change history

This is a curated history of user-impacting changes to the Squad distro, maintained by contributors as changes land.
It is not an exhaustive repository log and does not represent a root package version or release; independently released packages keep their own generated changelogs and release histories.

## Unreleased

- Add an escaped-defect linkage: `bin/sq-verification.sh record <issue-url> --discovered-at <ISO-8601> --pr <pull-url> --sha <full-sha>` writes the defect's discovery time, affected merged PR and full SHA, reproduction or an explicit unknown reason, the regression scenario now covering it, and the pre-merge gate that missed it into the existing issue body, and `report <owner/repo>` prints every recorded defect while naming each absent field as unknown rather than as success; issue bodies are read back through the `sq-gh` TOON decoder in bounded chunks that refuse a read the CLI truncated, so a re-record keeps the text preceding the recorded section.
  Record and report tests cover a real recorded defect, a fully-unknown record, multi-line values, preserved issue bodies including non-BMP text, empty values without reasons, and truncated or uppercase SHAs.
- Add an exact-prompt answer path for a supervised TUIOS operator blocked on a dialog, and wake that supervision from TUIOS's own agent-state events: `bin/sq-send.sh <task-id> --respond <action> <prompt-id> [value]` re-reads the current prompt, requires the same `prompt_id`, checks the action and the displayed option, and then lets the answering pane's `respond` grant decide, while the sentry subscribes before its baseline reconciliation, re-reads the exact window and prompt before applying the wake policy, and returns to the ordinary `SQUAD_POLL` reconcile when `subscribe` is absent or the stream gaps. The blocked wake and `bin/sq-crew-state.sh` name the exact `prompt_id` with the question and its numbered options, so the actor the question is routed to can form the prompt-bound answer through sanctioned Squad surfaces without a raw session-provider read.
- Return fresh read-only context when a TUIOS answer names a stale prompt id: every action gets a `tuios_prompt_recovery` snapshot with the attempted answer and the current target, prompt id, actions, options, and prompt, or the explicit nonblocked read or read failure when no prompt remains; a changed-prompt refusal performs one recovery read that reports the new prompt, a nonblocked pane, or an explicit read failure; a `settled_by=prompt` settlement returns that next prompt's snapshot for a fresh decision; and an unconfirmed write stays unresolved with its diagnostic and no retry even when the same prompt remains visible.
- Change TUIOS delivery to be queue-only: a pane with no attributable agent is now refused as `verdict=no_agent` with nothing typed, replacing the previous literal-write fallback that forced Enter and reported `verdict=uncertain-delivery`; `bin/sq-send.sh` reports that refusal as nothing typed rather than as an unconfirmed send, so a steer that previously reached such a pane by literal write is now refused by name with no keystroke.
- Detect an Orca operator blocked on a permission or question and escalate it immediately through the existing backend-neutral transition contract instead of waiting for the stale-pane wedge timer: the sentry polls Orca's exact-terminal `agentWait` observation, wakes once per distinct prompt against the exact terminal, and clears the escalation when the operator resumes. An absent or unreadable observation is never read as clear: before escalation the terminal keeps the existing supervision unchanged, and after an escalation it keeps its markers and is deliberately held out of the stale/wedge poll until a readable read proves the wait gone. The non-null record's shape and meaning remain unverified and fake-CLI-tested only.
- Stop a declared `paused:` from hiding unfinished or stuck work: the sentry now escalates an idle task whose recorded worktree stays dirty, a declared pause older than `SQUAD_PAUSE_MAX_SECS` (default 3600s, one escalation per declaration until it is renewed or cleared), and a byte-identical complete pane that keeps showing a stuck signature (compaction banner, cancelled or interrupted turn, error dialog), each naming its evidence in the `stale:` reason.
  Busy panes with changing output, clean worktrees, active drill run-steps, and terminal statuses keep their existing behavior, and away mode delivers this evidence as an ordinary daemon escalation instead of absorbing it as a routine pause recheck.
  `SQUAD_PANE_SIGNATURE_RE` adds one operator pattern and `SQUAD_PANE_SIGNATURE_{CANCELLED,COMPACTION,ERROR}_RE` replace the built-in signature sets; an unreadable complete viewport is logged as cannot-evaluate rather than read as progress or a stall.
- Fix drill custody recovery deadlocking on a terminal run whose recorded pipeline head no longer exists: `drill axi sync --recover` proves the object is absent from both the invoking repository and the local gate, records the loss and the custody return atomically, and the human and TUI surfaces state plainly that the pipeline's unpublished fixes are lost with it instead of claiming they are preserved.
  A fresh `drill axi run` then starts from the audited released local head or a proven descendant through a private submission ref, and a stale submission left by a failed start never wedges a later start while a live run still refuses.
  A merged or closed pull request retires the branch, and every release and fresh-start path refuses a retired branch with a named error.
- Add explicit-only away-mode supervision for an Orca-hosted Pi primary through a backend/harness-neutral native request/acknowledgement contract, launched and cleaned up as an exact owned Orca terminal whose create call requests no focus flag; filter semantics, real create/cleanup/focus behaviour and Android operation remain unverified, Pi is the only proven receiver, and every other harness refuses by name before mutation.
- Detect frozen busy agents using the existing static-pane timer, including the rendered cost/token gauge, and report `busy expired without activity`; changing output resets the timer, while declared pauses and active drill run-steps still suppress wedge alarms.
  This replaces the completed-turn age bound and removes `SQUAD_BUSY_TURN_MAX_SECS`.
  Busy expiry hashes the complete rendered viewport on tmux, zellij and tuios; unverified Herdr/Orca viewport interfaces and the missing verified cmux viewport read return cannot-evaluate and log a named limitation instead of raising a false alarm.
  Each changed-output episode, busy or idle, restarts away-mode timing; entering away mode mid-episode delivers its own handoff, and clearing busy on an unchanged pane preserves immediate idle surfacing.
  Transient capture failures retain retryable episode ownership but require a fresh full static window after recovery; finished tasks clear the wedge timer without hiding a newer active run.
  A static busy pane whose task is already done or failed in the current authoritative state is absorbed rather than escalated, and an active run-step still outranks an old terminal status.
  Measured whole-viewport capture on a representative TUIOS pane: mean 33.185 ms per read, not a difference-of-means cost (`/home/rehem/Projects/squad/data/squad-sentry-busy-expiry/capture-cost.md`).
- Fix a false possible-wedge alarm while a task legitimately waits on a foreground drill gate or CI monitor: the sentry no longer escalates an idle pane whose drill run-step is active, and still escalates a frozen pane once no step is active.
- Fix `bin/sq-spawn.sh` launching a brief that still carries the literal `{TASK}` placeholder: it now refuses before the endpoint is created and names the brief to edit.
- Fix Squad reporting execution state that contradicted the task's current Drill run: `bin/sq-crew-state.sh` now prefers the branch/head-bound run-step over a stale terminal status line, names `source: run-step` for the run it used, `bin/sq-exec-state.sh get` projects that run's lifecycle while `get-recorded` keeps the raw dispatch record, a retry deadline is cleared once the retry actually starts, and recovery repairs only queued/claimed/running attempts through existing transitions so a released id is never resurrected. A newer bound running run on the same branch replaces an older terminal snapshot, while unrelated or divergent runs stay untrusted; a gate-parked run keeps its attempt bound while the recorded owner endpoint is alive and becomes resumable once that endpoint is authoritatively gone; busy/paused precedence and escalation thresholds are unchanged.
- Fix drill operators stopping after failed-run custody recovery: generated instructions now use [`sq-drill-drive.sh`](bin/sq-drill-drive.sh) for bounded continuation without bypassing approval gates.
  Automatic resume is deliberately limited to unpublished custody recovery; a run that stopped after the pipeline pushed (behind/synchronized) reports blocked instead of auto-syncing because published-branch sync and divergence require separate authorization.
  The reported state is the value exposed by `axi status` when available; synchronized post-push state may be omitted there.
- Fix the always-on sentry waking Squad for a torn-down task's surviving `state/<id>.status` or `state/<id>.turn-ended` file: a signal whose `state/<id>.meta` is gone is now dropped with its `.seen-*` marker at each signal scan and again at the wake boundary after the grace re-scan, while a live task's turn-end still wakes normal supervision.
- Add `bin/sq-pane-grants.sh`, a respond-only TUIOS pane-grant surface (`show`, `grant respond`, `verify`) so supervision can answer an operator's blocked approval dialog: it adds only `respond` to one named pane, prints the exact copy-paste command the person must run once outside TUIOS, and `bin/sq-send.sh` reports the wrapper instead of the provider's raw grant advice that Squad's raw-session guard refuses.
- Make the execution-playbook choice an explicit intake decision: `bin/sq-brief.sh` now refuses a strike or recon scaffold that passes neither `--playbook <id>@<version>` nor a one-line `--no-playbook` reason, records that decision in the brief, and still refuses both flags together, an empty reason, or an XO charter carrying `--no-playbook`.
- Add a **profile** category beside playbooks and gates: a profile is a reusable constraint set that a brief attaches to a playbook with `bin/sq-brief.sh --playbook <id>@<version> --profile <id>@<version>`, while the playbook keeps the sequence, completion evidence, and stop condition and a gate stays a mechanical check; `react@1` is reclassified as the first profile, carrying the commander's FSD layering, kebab-case and named-function component convention, component-responsibility boundary, and TanStack Router/Query standard plus its proposed oxlint rule set for deliberation, with its evidence recorded as profile evidence instead of a validated checklist so the attached playbook keeps the completion gate.
- Add a `knowledge-pass` skill so a PR handoff becomes a code-grounded five-section pass (problem, rules, flow, decisions, verification) plus a one-question-at-a-time understanding check, shipped as an internal skill with a standalone public copy.
- Fix the per-task PR cost report to include every Drill pipeline invocation, attribute usage by provider-qualified model, render money to cents labeled provider-recorded versus estimate, and never present OpenCode Go flat-rate subscription usage as spend.
- Add a `--grimoire-output` mode to the skills registry generator that emits a schema-compliant registry for the Grimoire skills MCP from public `skills/` only, plus an optional `--grimoire-payload-dir` payload and a manual GitHub Pages workflow, leaving the legacy `skills-registry.json` unchanged.
- Fix the skills registry publishing an empty description for most entries whose `SKILL.md` declares it as a YAML block scalar; folded and literal block scalars are now read in full while a genuinely absent description still publishes empty.
- Fix the always-on sentry re-escalating a declared `paused:` (or commander-held) operator as a possible wedge whenever its pane stayed busy, or silently missing its first bounded recheck while a foreground long poll kept changing the pane; the declared pause now keeps the bounded long-pause recheck cadence on later polls.
- Add away-mode supervision for a TUIOS-hosted Pi primary, using a guarded detached daemon session and a durable Pi-native follow-up handoff that falls back to typing only into a composer it has read as empty.
- Fix operator sessions aborting on every Pi context compaction now that the compaction-resilience extension persists its state through the supported extension API.
- Initial history scope: future user-impacting distro changes will be recorded here. Earlier history is intentionally not reconstructed.
