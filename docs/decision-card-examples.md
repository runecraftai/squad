# Decision Card Examples

Three worked examples of the prose block and the card behind it.
The prose blocks below are generated by `bin/sq-ask.sh --render` from the fixtures in `tests/fixtures/decision-prose/`, and a test keeps them identical.
The schema and rules live in [Decision Card Payload Standard](decision-card-standard.md).

## Example 1: Keyed merge decision

A drill task finished validation and needs the commander to pick a merge strategy.
The card is `tests/fixtures/decision-prose/merge.json`; free text is off.

```text
D1 - Merge Strategy (ref: merge-strategy)
  How should we merge the authentication fix PR?
  Context: PR #42 fixes the OAuth token refresh bug. CI is green, 2 commits, time-sensitive.
  O1 - Squash & Merge: Combine into one clean commit on main (recommended)
  O2 - Rebase & Merge: Preserve both commits in history
  O3 - Create Merge Commit: Standard merge with a merge commit message
```

The worker's status line:

```
needs-decision [key=merge-strategy]: Merge Strategy | options: Squash & Merge|Rebase & Merge|Create Merge Commit | default: Squash & Merge
```

The commander types `d1 o2`.
Squad resolves it against the card and answers with the label, never the code:

```bash
bin/sq-ask.sh --answer 'd1 o2' --format text < tests/fixtures/decision-prose/merge.json
sq-send <task> --resolve-key merge-strategy "Rebase & Merge"
```

## Example 2: Drill review gate

Drill reports two ask-user findings and offers only a gate-level response.
Squad authors the card from `drill axi status`; each option's payload holds the exact `drill axi respond` arguments.
The card is `tests/fixtures/decision-prose/gate.json`.

```text
F1 - review-1 src/a.go:10 - flags an intentional guard
F2 - review-2 src/b.go:44 - asks for a new compatibility layer

D1 - Review gate: 2 open findings (ref: review-gate-1)
  Accepted intent does not require the compatibility layer.
  O1 - Fix F1 and F2: apply both as proposed (recommended)
  O2 - Accept as is: keep the code, finish this step
  O3 - Skip the step: do not run this check
  O0 - Your own words
```

The commander types `d1 o1`; the result carries the payload unchanged:

```json
{"decision_id":"review-gate-1","selected_option_id":"fix-all","selected_label":"Fix F1 and F2",
 "selected_payload":{"action":"fix","step":"review","findings":["review-1","review-2"]},
 "free_text":null,"method":"prose"}
```

Squad sends the worker the decision key, step, action, finding ids, and the exact response command, with `--resolve-key review-gate-1`.
A typed answer such as `d1 o0 "fix only the first one"` is Squad's judgment: it restates the resolved arguments before sending.

## Example 3: Product-scope choice

A worker needs the commander to decide whether to widen scope.
The card is `tests/fixtures/decision-prose/scope.json`; free text is on.

```text
D1 - Dashboard Scope (ref: dashboard-scope)
  Should the user dashboard include analytics widgets in the initial release?
  Context: The basic dashboard is done. Analytics widgets were in the original spec but could move to v2 to ship faster; adding them now costs about 2 days.
  O1 - Ship Without Analytics: Release with profile and activity only (recommended)
  O2 - Include Analytics: Add analytics widgets before release (+2 days)
  O3 - Analytics Behind Flag: Include analytics but gate them behind a feature flag
  O0 - Your own words
```

Answers: `d1 o2`, or `d1 o0 "ship it Friday"`.
Several decisions in one reply are answered together, `d1 o2 d2 o1`, and may be answered in part; the rest stay open.
